Nestor needs a **language model** for the agent, always, and **speech** services for the voice
channel, only if you use it. Both are set in `nestor.yaml`, their keys in the `.env` next to it.
`nestor init` writes OpenRouter and ElevenLabs: pick another provider below, paste its blocks over
the matching ones, then run `nestor check`.

## Language model

The agent talks to any server that speaks the OpenAI Chat Completions API, with streaming. The
adapter is tested against OpenRouter; the others speak the same API and are expected to work. Pick
a model that supports tool calls: the agent acts through them.

`llama-server` listens on 8080 by default, the admin’s port: start it with `--port 8081`. It serves

The model names are examples: any model of the provider’s catalogue that supports tool calls will
do, and any other OpenAI-compatible host works the same way. On most home hardware a local model
answers more slowly than a hosted one, and the voice channel feels it first. With Docker,
`localhost` is the container itself: use `host.docker.internal` instead, and on Linux add
`extra_hosts: ["host.docker.internal:host-gateway"]` to the `nestor` service of `compose.yaml`.

`model` also takes `extra_body`, merged into every request (OpenRouter’s routing, reasoning
settings…), `connect_timeout_s` (5) and `read_timeout_s` (30). A `triage_model` with the same keys
gives the sorting of incoming items to a smaller model.

## Speech

The voice channel transcribes the person and speaks the answer. ElevenLabs is the one provider
today, for both; a new one ships once it holds up on reproducible measurements (latency, turn
ends, interruptions).

<Providers kind="speech" locale="en">
<ProviderSetup kind="speech" brand="elevenlabs">

Scribe v2 Realtime transcribes, v4 Turbo speaks; one key covers both.

```bash
ELEVENLABS_API_KEY=sk_...
```

```yaml
channels:
  - kind: voice
    room: salon
    host: 0.0.0.0
    speech:
      api_key: ${ELEVENLABS_API_KEY}
      voice_id: GPAQQPp9dazaB2bl4zg9
      language: fr
```

`voice_id` is any voice of your ElevenLabs library. `language` is what the transcription listens
for (`fr` by default, `en` for English); the voice follows the language of the text.

</ProviderSetup>
</Providers>

## Without voice

Nestor works without a voice channel: talk to it through Telegram, with no speech provider. Replace
the `voice` entry of `channels` with:

```yaml
channels:
  - kind: telegram
    token: ${TELEGRAM_BOT_TOKEN}
```

```bash
TELEGRAM_BOT_TOKEN=123456:ABC-...
```

The token comes from Telegram’s [@BotFather](https://t.me/BotFather). Add `"telegram:<your chat id>"`
to your `accounts` in `household` so the bot knows you. Keep the `voice` extra installed all the
same (see [Install](/docs/install/)).

## Where keys live

- **`.env`**, next to `nestor.yaml`, referred to as `${NAME}`: what `nestor init` writes and the
  blocks above use. A variable already set in the environment (the shell, a service manager,
  Docker) wins over the file.
- **The vault**, encrypted in the data folder, referred to as `${secret:name}`: set with
  `nestor secrets set <name>` (asked without echo) or from the admin, listed with
  `nestor secrets list`. Better once the installation settles: no key in clear on disk, and the
  admin can change them.

```bash
nestor secrets set openrouter   # then, in nestor.yaml: api_key: ${secret:openrouter}
```

`NESTOR_SECRET_KEY`, in `.env`, opens the vault. `nestor init` generates it: never change it, or the
secrets already stored can no longer be read. Restart Nestor after changing a key.

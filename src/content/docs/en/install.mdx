Install Nestor on a machine that stays on: a computer, a mini PC or a Raspberry Pi.

## Choose a way

Python package [`nestor-home`](https://pypi.org/project/nestor-home/) (3.12+), or image
`ghcr.io/nestor-home/nestor` (amd64, arm64).

| Install with                 | uv                                     | pip                               | Docker                              |
| ---------------------------- | -------------------------------------- | --------------------------------- | ----------------------------------- |
| Python                       | uv fetches it if needed                | yours, 3.12 or later              | inside the image                    |
| Configuration, `.env`, state | the folder where you ran `nestor init` | same                              | the folder mounted on `/data`       |
| Upgrade                      | `uv tool upgrade nestor-home`          | `pip install -U nestor-home`      | `docker pull`, then a new container |
| Good for                     | trying it out, writing satellites      | an environment you already run    | a server at home that stays on      |

The package alone runs text only; the image has both extras. A missing extra stops Nestor at start,
naming the command to run.

| Extra      | Adds                                                     |
| ---------- | -------------------------------------------------------- |
| `voice`    | the satellites' realtime voice                           |
| `voice-id` | [recognising who speaks](/docs/agent/speakers/)          |

## Install and run

<Tabs set="install" locale="en">
<Tab set="install" choice="uv">

```bash
uv tool install 'nestor-home[voice]'   # or nestor-home, without the satellites' voice
mkdir nestor && cd nestor
nestor init
```

Fill the empty keys in `.env`, then:

```bash
nestor check
nestor run
```

`nestor` reads `nestor.yaml` and `.env` in the current folder, or `-c <file>`.

</Tab>
<Tab set="install" choice="pip">

```bash
python3 -m venv ~/.venvs/nestor
~/.venvs/nestor/bin/pip install nestor-home
mkdir nestor && cd nestor
~/.venvs/nestor/bin/nestor init
```

Fill `.env`, then `nestor check` and `nestor run`. Voice: `'nestor-home[voice]'`.

</Tab>
<Tab set="install" choice="docker">

Everything lives in a folder mounted on `/data`:

```bash docker-quickstart
docker run -it --rm -v ./nestor:/data ghcr.io/nestor-home/nestor init
$EDITOR nestor/.env
docker run -d --name nestor --restart unless-stopped -v ./nestor:/data -p 8470:8470 -p 8471:8471 ghcr.io/nestor-home/nestor
```

The container runs as uid 1000. Port 8470 is the admin, 8471 the satellites (`admin.port` and the
satellites channel's `port`, plus `-p`).

Other commands run through the image:

```bash
docker run --rm -v ./nestor:/data ghcr.io/nestor-home/nestor check
docker run --rm -it -v ./nestor:/data ghcr.io/nestor-home/nestor secrets list
```

After editing `nestor/.env`, `docker restart nestor`. A local model server (Ollama, LM Studio) is
at `http://host.docker.internal:<port>/v1`; on Linux, add
`--add-host host.docker.internal:host-gateway`.

### With Compose

[`compose.yaml`](https://github.com/nestor-home/nestor/blob/main/compose.yaml) adds an optional
Litestream replica and keeps everything in `./data`:

```bash
curl -fsSLO https://raw.githubusercontent.com/nestor-home/nestor/main/compose.yaml
docker compose run --rm nestor init
docker compose up -d
```

Upgrade: `docker compose pull`, then `docker compose up -d`. It follows `latest`; pin a line with
`ghcr.io/nestor-home/nestor:<major>.<minor>`.

</Tab>

## The owner account

`nestor init` creates it. Without one (hand-written configuration, `state/` from elsewhere):

```bash
nestor accounts create-owner --login alex
```

`--person` picks the member (the first by default). Restart Nestor. With Docker, prefix with
`docker run --rm -it -v ./nestor:/data ghcr.io/nestor-home/nestor`.

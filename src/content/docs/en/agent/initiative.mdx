## What calls for it

| Source      | Example                                 | Tool                                             |
| ----------- | --------------------------------------- | ------------------------------------------------ |
| **Alert**   | "tell me when the bank writes"          | `create_alert`                                   |
| **Task**    | "read this PDF and sum up the contract" | `start_task`, to an [executor](/docs/executors/) |
| **Message** | "ask Léa if she needs the car"          | `message_person`                                 |

Each has a title, shown in the admin, and reaches whoever asked.

- **Task**: its result and files are announced once, even after a restart.
- **Message**: one expecting a reply stays an open question for both people. `may_message` limits
  whom a person may write to (default `"*"`, always themselves).

## Alerts

An alert is something to do later, regularly, or when something happens. The agent sets it with
`create_alert`, lists it with `list_alerts` and cancels it with `cancel_alert`.

| Part        | Values                                                                                     |
| ----------- | ------------------------------------------------------------------------------------------ |
| trigger     | once at a date and time (`at`), at `times` on `days`, or as items of some `kinds` arrive    |
| instruction | what the agent does when it rings, and for whom                                            |
| condition   | optional, in the person's words: "the share is under 135 $"                                 |
| frequency   | `once`, `every_time`, or `until_rung` (until it has told something); `until` ends any of them at a date |
| urgent      | told at once, even in quiet hours; set at creation                                          |

| Request                                       | Trigger              | Frequency    |
| --------------------------------------------- | -------------------- | ------------ |
| "remind me tomorrow at 9 to call the plumber" | `at`                 | `once`       |
| "every weekday at 8, tell me the weather"     | `times`, `days`      | `every_time` |
| "tell me when the parcel arrives"             | `kinds: [mail]`      | `once`       |
| "tell me once the share is under 135 $"       | `times`, condition   | `until_rung` |
| "tell me when the dishwasher is done"         | `kinds: [dishwasher]` | `once`      |

When it rings, the agent follows the instruction with its tools. A condition on a time is checked
with them first; when it does not hold, nothing is said. An item (a [mail](/docs/accounts/#mail-and-alerts),
a feed entry, a page change) is read by a small model (`alerts.model`), once for every alert it may
concern; a mail, feed or page alert needs a condition saying what to recognise. An event of a
[webhook](/docs/tools/#feeds-pages-and-webhooks) kind rings an alert without a condition as it
arrives, with no model.

Each alert keeps its thread: when it rings again, the agent rereads what it told before and says
only what is new. One due while Nestor was stopped rings once at the next start. The journal and
the admin keep why each ring happened: its time came, an event arrived, or an item matched, with
the model's summary.

## Where it arrives

The **courier** decides, from [Home Assistant](/docs/home/) presence, and journals why.

| The person                    | Nestor                                                        |
| ----------------------------- | ------------------------------------------------------------- |
| asked for writing, or is away | writes where they read (their `reach`)                        |
| is in a room with a satellite | speaks there                                                  |
| is home, in no known room     | speaks through `initiative.main_room`                         |
| is in a room without one      | writes                                                        |
| has no presence at all        | writes; speaks only into an ongoing spoken conversation, or to someone with nowhere to write |

| Case            | Then                                                                                  |
| --------------- | ------------------------------------------------------------------------------------- |
| no reaction     | a spoken message follows in writing after `initiative.follow_up_after_s` (180 s)       |
| quiet hours     | `initiative.quiet_hours` (`"22:30-07:30"`): nothing spoken unless urgent, still written |
| private content | the room hears that something came; the content is written                            |
| files           | written with the files; the room hears what they bring                                 |

A spoken message is heard by everyone in the room ([Speakers](/docs/agent/speakers/)).

## How it ends

Only the agent's final answer goes out, never "let me check".

| Outcome         | When                                                | Then                                   |
| --------------- | --------------------------------------------------- | -------------------------------------- |
| passed on       | it reached the person                               | it stays in the conversation's history |
| nothing to tell | a check found nothing new                           | nothing sent, the reason journaled, never retried |
| not passed on   | no channel took it, or the model could not write it | tried again at the next start          |

Only an alert may end with nothing to tell. A request, a message, a confirmation and
a failure are always told.

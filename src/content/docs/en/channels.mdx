People reach Nestor through `channels`. All share one agent and one memory: a question asked in the
kitchen can go on from the admin.

## Choose channels

<Providers kind="channel" locale="en">
<ProviderSetup kind="channel" brand="chat">

Write to Nestor from the admin, under **Chat**. `nestor init` adds it:

```yaml
channels:
  - kind: web
```

Each chat is its own thread, listed under its [title](/docs/models/#roles); the memory is the same
in all. Answers appear as they are written, with the tools Nestor uses, and **Stop** ends one. An
answer goes on when you leave the page and shows again when you come back. What Nestor brings by
itself for a chat, such as a task’s result, lands in it.

The chat is open to admin accounts linked to a person of the household; the owner `nestor init`
creates is linked to the first one. It takes photos, files and voice messages recorded in the
browser: see [below](#photos-and-voice-messages).

</ProviderSetup>
<ProviderSetup kind="channel" brand="telegram">

Create a bot with [@BotFather](https://t.me/BotFather) and put its token in `.env`:

```ini
TELEGRAM_BOT_TOKEN=123456:ABC-...
```

```yaml
channels:
  - kind: telegram
    token: ${TELEGRAM_BOT_TOKEN}
```

Add `"telegram:<your user id>"` to your `accounts` in `household`. To find the id, write to the bot:
the server’s log prints the id of each stranger it ignores. It also reads photos and voice messages:
see [below](#photos-and-voice-messages).

</ProviderSetup>
<ProviderSetup kind="channel" brand="discord">

Create an application in the [Developer Portal](https://discord.com/developers/applications), add a
bot, turn on its **Message Content** intent and invite it to your server. Then:

```yaml
channels:
  - kind: discord
    token: ${DISCORD_BOT_TOKEN}
```

It answers direct messages, and messages that mention it in a server's channels. Add
`"discord:<your user id>"` to your `accounts`.

</ProviderSetup>
<ProviderSetup kind="channel" brand="slack">

Create a Slack app with Socket Mode on, an app-level token (`connections:write`) and a bot token with
`chat:write`, `files:read`, `files:write`, `im:history` and `app_mentions:read`, subscribed to the
`message.im` and `app_mention` events. No public address is needed.

```yaml
channels:
  - kind: slack
    app_token: ${SLACK_APP_TOKEN}
    bot_token: ${SLACK_BOT_TOKEN}
```

It answers direct messages and mentions. Add `"slack:<your member id>"` to your `accounts`.

</ProviderSetup>
<ProviderSetup kind="channel" brand="matrix">

Create an account for the bot on a homeserver and take its access token. Invite it to a room: it
joins and answers there.

```yaml
channels:
  - kind: matrix
    homeserver: https://matrix.org
    token: ${MATRIX_TOKEN}
```

Add `"matrix:@you:matrix.org"` to your `accounts`. Encrypted rooms are not read: create the room
without encryption.

</ProviderSetup>
<ProviderSetup kind="channel" brand="signal">

Register a number with [signal-cli-rest-api](https://github.com/bbernhard/signal-cli-rest-api), in its
`normal` or `native` mode, then:

```yaml
channels:
  - kind: signal
    url: http://signal:8080
    number: "+33612345678"
```

It answers direct messages and groups. Add `"signal:+33…"`, your number, to your `accounts`. A voice
message is answered in writing.

</ProviderSetup>
<ProviderSetup kind="channel" brand="satellites">

Devices people type on, talk to, or both. In writing:

```yaml
channels:
  - kind: satellites
    host: 0.0.0.0
```

`host: 0.0.0.0` opens port 8471 to your network. Aloud, add a [voice](#voice). Then [pair
them](/docs/satellites/). Anyone in the room can talk to a satellite: see
[Speakers](/docs/agent/speakers/).

</ProviderSetup>
</Providers>

## Voice

Talking aloud needs the `voice` extra, `nestor-home[voice]` ([Installation](/docs/install/)). The
Docker image has it.

<Providers kind="speech" locale="en">
<ProviderSetup kind="speech" brand="elevenlabs">

One key covers two models: one hears people (Scribe v2 Realtime), the other gives the assistant its
voice (v4 Turbo). Both are [models](/docs/models/#hearing-and-speaking), named in the `voice` block.

```ini
ELEVENLABS_API_KEY=sk_...
```

```yaml
models:
  ears:
    type: transcription
    provider: elevenlabs
    api_key: ${ELEVENLABS_API_KEY}
  voice:
    type: speech
    provider: elevenlabs
    api_key: ${ELEVENLABS_API_KEY}
    voice_id: GPAQQPp9dazaB2bl4zg9

channels:
  - kind: satellites
    host: 0.0.0.0
    voice:
      transcription: ears
      speech: voice
```

`voice_id` is any voice of your library. Transcription expects English unless the model sets
`language` (`fr`, `de`…). Voice messages are read by `file_model` (`scribe_v2`), since the realtime
model does not read files.

</ProviderSetup>
<ProviderSetup kind="speech" brand="openai">

Any API that speaks OpenAI's `/audio/transcriptions` and `/audio/speech`: OpenAI, Groq and Mistral
for hearing, OpenAI for speaking.

```yaml
models:
  ears:
    type: transcription
    provider: openai-compatible
    base_url: https://api.groq.com/openai/v1
    api_key: ${GROQ_API_KEY}
    model: whisper-large-v3-turbo
  voice:
    type: speech
    provider: openai-compatible
    base_url: https://api.openai.com/v1
    api_key: ${OPENAI_API_KEY}
    model: gpt-4o-mini-tts
    voice: alloy
```

Transcription hears the household's language unless `language` says otherwise. Satellites hear a
turn once it ends: the first words wait for it.

</ProviderSetup>
<ProviderSetup kind="speech" brand="nvidia">

Parakeet TDT v3 hears 25 European languages on Nestor's own machine: no key, nothing said leaves the
house. It needs `nestor-home[voice,voice-id]`, downloads half a gigabyte once, and takes about 1 GB of
memory.

```yaml
models:
  ears:
    type: transcription
    provider: sherpa-onnx
    model: parakeet-v3
```

</ProviderSetup>
<ProviderSetup kind="speech" brand="kokoro">

Kokoro speaks on your own machine through a server that speaks OpenAI's API, such as Kokoro-FastAPI
or speaches. Run it beside Nestor, then point a speech model at it; it needs no key.

```yaml
models:
  voice:
    type: speech
    provider: openai-compatible
    base_url: http://localhost:8880/v1
    model: kokoro
    voice: ff_siwis
```

`ff_siwis` is Kokoro's French voice; `af_heart` and `bm_george` speak English.

</ProviderSetup>
<ProviderSetup kind="speech" brand="whisper">

Whisper hears on your own machine through a server that speaks OpenAI's API, such as speaches or
whisper.cpp's server. Point a transcription model at it; it needs no key.

```yaml
models:
  ears:
    type: transcription
    provider: openai-compatible
    base_url: http://localhost:8000/v1
    model: Systran/faster-whisper-small
```

</ProviderSetup>
</Providers>

The `voice` block also takes:

- `style`: how the assistant writes for this voice, such as its expression tags;
- `fallback_clips`: a folder with `stt.wav` and `tts.wav`, recorded in the same voice, played when
  the speech model is down.

## Photos and voice messages

Messaging channels, the admin’s chat included, pass on photos, voice messages, audio files and
documents, with their caption. Nestor keeps them with its journal, where the admin shows them. The
chat takes up to 10 files of 20 MB each per message.

- A voice message is transcribed by a `transcription` model. When a `speech` model is set and the
  channel can send voice messages, the answer is one too.
- A photo goes to the model when its profile sees images (`vision: true`). Otherwise the model says
  it cannot see it.
- A PDF or a text file is read: the model reads its text in parts, where it was sent or by whoever
  sent it. A scan has no text to read, and the model says so.
- Any other file is named to the model, which says it cannot open it.

The pictures Nestor draws go with its answer, on the channels that show pictures ([Pictures](/docs/models/#pictures)).

```yaml
models:
  chat:
    type: language
    provider: openai-compatible
    base_url: https://openrouter.ai/api/v1
    api_key: ${MODEL_API_KEY}
    model: anthropic/claude-haiku-5.5
    vision: true
  ears:
    type: transcription
    provider: elevenlabs
    api_key: ${ELEVENLABS_API_KEY}
    language: en
  voice:
    type: speech
    provider: elevenlabs
    api_key: ${ELEVENLABS_API_KEY}
    voice_id: GPAQQPp9dazaB2bl4zg9
```

`agent.transcription` and `agent.speech` name these models; each defaults to the only one of its
type ([Roles](/docs/models/#roles)).

## Mentions

On every channel, a message can name with `@` what it is about:

| Written    | Names                                          | Nestor                                  |
| ---------- | ---------------------------------------------- | --------------------------------------- |
| `@sam`     | a person of the household                      | writes to them what is for them         |
| `@kitchen` | a room of the home, from Home Assistant        | does what the message asks in that room |
| `@hermes`  | an [executor](/docs/connections/#longer-tasks) | hands it that part of the work          |
| `@gmail`   | a service of a connected account               | uses that account’s tools for it        |

A person is named by their `id`, a room by its Home Assistant area, an executor by its name. A
connector names the services of its accounts: `@gmail` for a Google account, `@mail` for an IMAP
mailbox. With two accounts of one service, the start of the address tells them apart:
`@gmail-alex`.

Case and accents do not count, and names answer to aliases: a person’s or a room’s name
(`@Léa`, `@living-room`), an account’s address or its start. A name that matches nothing, or an
e-mail address, stays a word. Each person can name only what they may use: their own accounts and
the household’s, never someone else’s.

The admin’s chat suggests names as you type `@`. Each one is logged with the turn and told to the
model in that turn’s instructions.

## When a conversation ends

After a silence, the next message starts a new conversation and the last one goes to
[memory](/docs/agent/memory/). The silence is 5 minutes aloud, 4 hours in writing; set
`conversation_ends_after_s` per channel to change it.

People reach Nestor through `channels`. All share one agent and one memory: a question asked in the
kitchen can go on from the admin. To talk aloud, see [Voice](/docs/voice/).

## Choose channels

<Providers kind="channel" locale="en">
<ProviderSetup kind="channel" brand="chat">

The admin’s **Chat**. `nestor init` adds it:

```yaml
channels:
  - kind: web
```

Each chat is a thread with its own [title](/docs/models/#roles); the memory is shared. Answers
stream in with the tools Nestor uses, **Stop** ends one, and an answer goes on when you leave the
page. A task’s result lands in the chat that asked for it.

Open to admin accounts linked to a person of the household; the owner `nestor init` creates is
linked to the first one.

</ProviderSetup>
<ProviderSetup kind="channel" brand="telegram">

Create a bot with [@BotFather](https://t.me/BotFather) and put its token in `.env`:

```ini
TELEGRAM_BOT_TOKEN=123456:ABC-...
```

```yaml
channels:
  - kind: telegram
    token: ${TELEGRAM_BOT_TOKEN}
```

To find your user id, write to the bot: the server’s log prints the id of each stranger it ignores.

</ProviderSetup>
<ProviderSetup kind="channel" brand="discord">

In the [Developer Portal](https://discord.com/developers/applications), create an application, add a
bot, turn on its **Message Content** intent and invite it to your server.

```yaml
channels:
  - kind: discord
    token: ${DISCORD_BOT_TOKEN}
```

It answers direct messages, and messages that mention it in a server.

</ProviderSetup>
<ProviderSetup kind="channel" brand="slack">

Create a Slack app with Socket Mode, an app-level token (`connections:write`) and a bot token with
`chat:write`, `files:read`, `files:write`, `im:history` and `app_mentions:read`, subscribed to
`message.im` and `app_mention`. No public address is needed.

```yaml
channels:
  - kind: slack
    app_token: ${SLACK_APP_TOKEN}
    bot_token: ${SLACK_BOT_TOKEN}
```

It answers direct messages and mentions.

</ProviderSetup>
<ProviderSetup kind="channel" brand="matrix">

Create an account for the bot on a homeserver, take its access token, and invite it to a room.

```yaml
channels:
  - kind: matrix
    homeserver: https://matrix.org
    token: ${MATRIX_TOKEN}
```

Encrypted rooms are not read: create the room without encryption.

</ProviderSetup>
<ProviderSetup kind="channel" brand="signal">

Register a number with [signal-cli-rest-api](https://github.com/bbernhard/signal-cli-rest-api), in
its `normal` or `native` mode.

```yaml
channels:
  - kind: signal
    url: http://signal:8080
    number: "+33612345678"
```

It answers direct messages and groups. A voice message is answered in writing.

</ProviderSetup>
<ProviderSetup kind="channel" brand="whatsapp">

A WhatsApp Business number through Meta’s Cloud API. In Meta’s app dashboard, add WhatsApp, take the
number’s id, a system user’s permanent token and the app’s secret. Point the webhook at
`https://<your host>/whatsapp` (proxied to port 8473) with a verify token you choose.

```yaml
channels:
  - kind: whatsapp
    phone_number_id: "1098…"
    token: ${WHATSAPP_TOKEN}
    verify_token: ${WHATSAPP_VERIFY_TOKEN}
    app_secret: ${WHATSAPP_APP_SECRET}
```

Every message is checked against Meta’s signature. A business may write freely only within 24 hours
of the person’s last message: a later reminder may be refused.

</ProviderSetup>
<ProviderSetup kind="channel" brand="email">

A mailbox of Nestor’s own: members write to it, the answer comes back in the thread.

```yaml
channels:
  - kind: email
    address: nestor@example.org
    username: nestor@example.org
    password: ${NESTOR_MAIL_PASSWORD}
    imap_host: imap.example.org
    smtp_host: smtp.example.org
```

Only mail your server authenticated (DMARC, or DKIM and SPF) is answered, since anyone can write a
`From` header. Turn `require_authenticated` off only for a local bridge that adds no such header.

</ProviderSetup>
<ProviderSetup kind="channel" brand="satellites">

Devices people type on, talk to, or both.

```yaml
channels:
  - kind: satellites
    host: 0.0.0.0
```

`host: 0.0.0.0` opens port 8471 to your network. To talk aloud, add a [voice](/docs/voice/). Then
[pair them](/docs/satellites/). Anyone in the room can talk to a satellite
([Speakers](/docs/agent/speakers/)).

</ProviderSetup>
<ProviderSetup kind="channel" brand="api">

Nestor answers `POST /v1/chat/completions` like a model: Open WebUI, LibreChat, a script, or Home
Assistant through a conversation integration that takes a base URL (Extended OpenAI Conversation).
Each key belongs to an account:

```yaml
channels:
  - kind: openai-api
    keys:
      mathis: ${NESTOR_API_KEY}
```

Point the client at `http://<nestor>:8472/v1`, model `nestor`, with that key. `host: 0.0.0.0` opens
it to other machines. Nestor keeps its own conversation: only your last message counts, pictures
included.

</ProviderSetup>
<ProviderSetup kind="channel" brand="ntfy">

Notifications on your phone through [ntfy](https://ntfy.sh). Subscribe to a topic in the ntfy app:

```yaml
channels:
  - kind: ntfy
```

On the public server, anyone who knows a topic can read it: pick one nobody would guess, or use your
own server with `url` and `token`. Nobody answers through it. Each file goes as its own notification; ntfy.sh keeps attachments
3 hours, 15 MB at most.

</ProviderSetup>
<ProviderSetup kind="channel" brand="webhook">

Each message Nestor sends by itself is posted as JSON: to a Home Assistant automation, n8n, a
script.

```yaml
channels:
  - kind: webhook
    url: https://homeassistant.local:8123/api/webhook/nestor
    secret: ${WEBHOOK_SECRET}
```

The body is `{"to", "text", "attachments"}`; each attachment carries its `kind` (`image`, `voice`,
`audio`, `file`), `name` and content. With `secret`, `X-Nestor-Signature: sha256=…` signs it, as
GitHub signs its webhooks.

</ProviderSetup>
</Providers>

## Who is who

Each person lists, in `household`, the account Nestor knows them by on each channel
([Configuration](/docs/configuration/#the-household)). Channels that only send take a `reach`.

| Channel    | In `accounts` or `reach`                        |
| ---------- | ----------------------------------------------- |
| Telegram   | `telegram:<user id>`                            |
| Discord    | `discord:<user id>`                             |
| Slack      | `slack:<member id>`                             |
| Matrix     | `matrix:@you:matrix.org`                        |
| Signal     | `signal:+33…`, your number                      |
| WhatsApp   | `whatsapp:<your number, digits only>`           |
| Email      | `email:you@example.org`                         |
| OpenAI API | `openai-api:<key name>`, such as `openai-api:mathis` |
| ntfy       | `reach: "ntfy:<topic>"`                         |
| Webhook    | `reach: "webhook:<to>"`, sent as `to`           |


## Photos and voice messages

Messaging channels, the admin’s chat included, pass on files with their caption. Nestor keeps them
with its journal, where the admin shows them. The chat takes up to 10 files of 20 MB each per
message.

| Received        | What Nestor does                                                                                       |
| --------------- | ------------------------------------------------------------------------------------------------------ |
| voice message   | transcribes it; answers with one when a speech model is set and the channel sends them ([Voice](/docs/voice/#voice-messages)) |
| photo           | shows it to a model that sees images (`vision: true`, `anthropic`, `gemini`); otherwise the model says it cannot see it |
| PDF, text file  | the model reads its text in parts; a scan has no text, and the model says so. `anthropic` and `gemini` read the last two PDFs whole, scans included |
| any other file  | names it to the model, which says it cannot open it                                                     |

What Nestor sends goes with its answer, under its name: the [pictures](/docs/models/#pictures) it
draws, the documents and audio files a task makes. Every messaging channel and the admin’s chat send
them.

## Mentions

On every channel, a message can name with `@` what it is about:

| Written    | Names                                     | Nestor                                  |
| ---------- | ----------------------------------------- | --------------------------------------- |
| `@sam`     | a person, by their `id`                   | writes to them what is for them         |
| `@kitchen` | a room, by its Home Assistant area        | does what the message asks in that room |
| `@hermes`  | an [executor](/docs/executors/), by name  | hands it that part of the work          |
| `@gmail`   | a service of a [connected account](/docs/accounts/) | uses that account’s tools for it |

A Google account answers to `@gmail` or `@calendar`, an IMAP mailbox to `@mail`, Linear’s MCP server
to `@linear`. When two accounts share a name, the least of the address that tells them apart follows
it: `@calendar-alex`, or `@calendar-alex-gmail`.

- Case and accents do not count. Names answer to aliases: a person’s or a room’s name (`@Léa`,
  `@living-room`), an account’s address or its start.
- A name that matches nothing, or an e-mail address, stays a word.
- Each person names only what they may use: their own accounts and the household’s.

The admin’s chat suggests names as you type `@`. Each name is logged with the turn and told to the
model.

## When a conversation ends

After a silence, the next message starts a new conversation and the last one goes to
[memory](/docs/agent/memory/).

| Channel | Silence   |
| ------- | --------- |
| aloud   | 5 minutes |
| written | 4 hours   |

Set `conversation_ends_after_s` on a channel to change it.

Nestor tells you when a release is out and what it changes. Update the server first, then the
satellites: a satellite updated before the server would speak a version the server refuses.

## New releases

Each release publishes `releases.json`: every release, its changes, the satellite protocol versions
it speaks. Nestor reads it a minute after it starts, then daily, and sends nothing but the request.

| Key     | Default                   | What it does                       |
| ------- | ------------------------- | ---------------------------------- |
| `check` | `true`                    | `false` never reads the feed       |
| `feed`  | the latest GitHub release | the feed’s address, for a mirror   |

The admin then shows **New release** at the bottom of the sidebar, with the notes since your
version, breaking changes first.

## Update the server

Installed with `uv tool` or pip:

<Steps>

1. **Install.** Click **Install**, then confirm.
2. **Check.** Nestor installs the release from PyPI with your extras and runs `nestor check`.
3. **Restart.** It restarts on it, cutting a conversation in progress. If a step fails, it puts the
   previous version back and says so.

</Steps>

With Docker, the dialog gives the commands. The admin never asks for the Docker socket: it would
give it root on the host.

```bash
docker compose pull
docker compose up -d
```

A development checkout updates with git. Until the first stable release, a breaking release may ask
you to recreate `state/` and pair the satellites again.

## Update a satellite

A satellite allowed `device.update` looks for a newer version daily, where it was installed from.

<Steps>

1. **Open.** Its page shows **Update available**, with the notes the device found.
2. **Install.** The device fetches the version itself. Nestor sends only the version it reported,
   never a file or an address, and never opens the notes’ link.
3. **Restart.** If the new version does not connect within a minute, the device goes back to the
   previous one and says so.

</Steps>

A satellite never installs an older version, or one it did not find
([protocol](/docs/satellites/protocol/#10-updates)). When a release drops a satellite’s protocol
version, its notes say so: update that satellite on the device itself, after the server.

L’agent pense avec un modèle de langage de votre choix, hébergé ou local, par l’API Chat
Completions d’OpenAI. Choisissez-en un qui gère les appels d’outils.

## Choisir un fournisseur

`nestor init` écrit un profil sous `models`, nommé `main`. Pour changer de fournisseur,
remplacez-le par un bloc ci-dessous et lancez `nestor check`. La clé va dans `.env`, en
`MODEL_API_KEY` ; les serveurs locaux n’en demandent pas.

Tout modèle qui gère les appels d’outils convient. Un modèle local répond plus lentement, et la
voix le ressent en premier.

Avec Docker, un serveur de modèle sur l’hôte est à `http://host.docker.internal:<port>/v1`. Sous
Linux, faites-le écouter sur toutes les interfaces : `OLLAMA_HOST=0.0.0.0` pour Ollama,
`--host 0.0.0.0` pour llama.cpp.

## Rôles

Avec plusieurs profils, chaque rôle nomme celui qu’il utilise :

| Rôle                   | Ce qu’il fait                                                        | Sans réglage       |
| ---------------------- | -------------------------------------------------------------------- | ------------------ |
| `agent.spoken`         | répond à voix haute : les premiers mots doivent venir vite           | `agent.written`    |
| `agent.written`        | répond par écrit, où quelques secondes ne gênent pas                 | `agent.spoken`     |
| `watches.model`        | trie le courrier entrant pour les veilles                            | `agent.written`    |
| `memory.consolidation` | résume chaque conversation une fois terminée                         | `agent.written`    |
| `agent.transcription`  | écoute les messages vocaux                                           | le seul modèle de transcription |
| `agent.speech`         | répond à un message vocal par un autre                               | le seul modèle de synthèse |

Un modèle rapide pour la voix, un plus solide pour le reste :

```yaml
models:
  quick:
    type: language
    provider: openai-compatible
    base_url: https://openrouter.ai/api/v1
    api_key: ${MODEL_API_KEY}
    model: anthropic/claude-haiku-5.5
  deep:
    type: language
    provider: openai-compatible
    base_url: https://openrouter.ai/api/v1
    api_key: ${MODEL_API_KEY}
    model: anthropic/claude-sonnet-5.5

agent:
  spoken: quick
  written: deep
```

## Recherche par le sens

Un modèle d’embedding permet à Nestor de retrouver ses souvenirs par le sens : « que mange
Léa ? » trouve « Léa est végétarienne ». Nommez un profil d’embedding dans `memory.embedder` :

```yaml
models:
  vectors:
    type: embedding
    provider: openai-compatible
    base_url: https://openrouter.ai/api/v1
    api_key: ${MODEL_API_KEY}
    model: openai/text-embedding-3-small
    dimensions: 1536

memory:
  embedder: vectors
```

Tout point `/embeddings` compatible OpenAI convient. `dimensions` est la taille des vecteurs.
Pour un modèle qui attend un préfixe (`query: `), réglez `query_prefix` et `document_prefix`. Changer de modèle réindexe en tâche de fond. Voir [Mémoire](/fr/docs/agent/memory/).

## Entendre et parler

`models` contient tous les modèles qu’utilise Nestor. Chacun dit son `type` et son `provider`, le
plugin qui sert ce type, et un réglage ne propose que les modèles de son type :

| Type          | Ce qu’il fait                      | Nommé dans                                                |
| ------------- | ---------------------------------- | --------------------------------------------------------- |
| language      | répond, à voix haute ou à l’écrit  | `agent` ([Rôles](#rôles))                                 |
| embedding     | retrouve les souvenirs par le sens | `memory.embedder`                                         |
| transcription | entend ce qu’on dit à un satellite, et les messages vocaux | `voice.transcription` d’un canal satellites, `agent.transcription` |
| speech        | donne sa voix à l’assistant        | `voice.speech` d’un canal satellites, `agent.speech` |
| speaker       | reconnaît qui parle                | `voices.embedder` ([Locuteurs](/fr/docs/agent/speakers/)) |

Configurer la voix : [Canaux et voix](/fr/docs/channels/#voix).

## Réglages

Un profil de conversation accepte aussi :

- `extra_body`, fusionné dans chaque requête (routage, raisonnement) ;
- `read_timeout_s`, en secondes (30) ;
- `cache_control`, pour le cache de prompt du fournisseur, actif par défaut pour OpenRouter et
  Anthropic ;
- `vision: true` pour un modèle qui lit les images : il voit alors les photos envoyées.

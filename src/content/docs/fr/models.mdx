## Choisir un fournisseur

`nestor init` écrit un profil, `models.main`. Pour changer de fournisseur, remplacez-le par un bloc
ci-dessous, puis `nestor check`. La clé va dans `.env`, en `MODEL_API_KEY` ; les serveurs locaux
n’en demandent pas.

Un modèle local est plus lent, et la voix le ressent en premier. Depuis Docker, utilisez
`http://host.docker.internal:<port>/v1` ; sous Linux, faites écouter le serveur sur toutes les
interfaces (`OLLAMA_HOST=0.0.0.0`, `--host 0.0.0.0` pour llama.cpp).

## Types

Chaque modèle a un `type` (`language`, `embedding`, `transcription`, `speech`, `speaker`, `image`)
et un `provider`. Voir [Voix](/fr/docs/voice/) et [Locuteurs](/fr/docs/agent/speakers/).

## Rôles

| Rôle                   | Ce qu’il fait                                               | Sans réglage                    |
| ---------------------- | ----------------------------------------------------------- | ------------------------------- |
| `agent.spoken`         | répond à voix haute : les premiers mots doivent venir vite  | `agent.written`                 |
| `agent.written`        | répond par écrit                                            | `agent.spoken`                  |
| `agent.titles`         | titre chaque discussion de l’admin ; un petit modèle suffit | `agent.written`                 |
| `watches.model`        | trie le courrier entrant pour les veilles                   | `agent.written`                 |
| `memory.consolidation` | résume chaque conversation une fois terminée                | `agent.written`                 |
| `agent.transcription`  | écoute les messages vocaux                                  | le seul modèle de transcription |
| `agent.speech`         | répond à un message vocal par un autre                      | le seul modèle de synthèse      |
| `agent.images`         | dessine les images                                          | le seul modèle d’images         |

Un modèle rapide pour la voix, un plus solide à l’écrit :

```yaml
models:
  quick:
    type: language
    provider: openai-compatible
    base_url: https://openrouter.ai/api/v1
    api_key: ${MODEL_API_KEY}
    model: anthropic/claude-haiku-5.5
  deep:
    type: language
    provider: openai-compatible
    base_url: https://openrouter.ai/api/v1
    api_key: ${MODEL_API_KEY}
    model: anthropic/claude-sonnet-5.5

agent:
  spoken: quick
  written: deep
```

## Réglages

| Clé              | Modèles                        | Rôle                                                                        |
| ---------------- | ------------------------------ | --------------------------------------------------------------------------- |
| `extra_body`     | tous les modèles de langage    | fusionné dans chaque requête (routage, raisonnement, `generationConfig`)    |
| `read_timeout_s` | tous les modèles de langage    | en secondes : 30 pour `openai-compatible`, 60 pour `anthropic` et `gemini`  |
| `fallback`       | tous les modèles de langage    | le modèle qui répond quand celui-ci échoue ([Modèle de secours](#modèle-de-secours)) |
| `vision`         | `openai-compatible`            | `true` pour un modèle qui lit les images : il voit alors les photos envoyées |
| `cache_control`  | `openai-compatible`            | le cache de prompt du fournisseur, actif par défaut pour OpenRouter et Anthropic |
| `price`          | tous les modèles               | ce qu’il coûte quand son fournisseur ne le dit pas ([Coûts](/fr/docs/costs/#donner-un-prix-à-un-modèle)) |

`anthropic` et `gemini` voient les images et lisent les PDF d’eux-mêmes.

## Modèle de secours

Quand un modèle échoue avant de répondre, son `fallback` répond, dans tous ses rôles, et le journal
le dit. Un modèle de secours peut avoir le sien, et ne reçoit pas les images ni les documents qu’il
ne sait pas lire.

```yaml
models:
  claude:
    type: language
    provider: anthropic
    api_key: ${ANTHROPIC_API_KEY}
    model: claude-sonnet-5-5
    fallback: gemini
  gemini:
    type: language
    provider: gemini
    api_key: ${GEMINI_API_KEY}
    model: gemini-flash-latest
```

Un modèle qui échoue en cours de réponse n’est pas remplacé.

## Recherche par le sens

Un modèle d’embedding retrouve les souvenirs par le sens (« que mange Léa ? » trouve « Léa est
végétarienne ») :

```yaml
models:
  vectors:
    type: embedding
    provider: openai-compatible
    base_url: https://openrouter.ai/api/v1
    api_key: ${MODEL_API_KEY}
    model: openai/text-embedding-3-small
    dimensions: 1536

memory:
  embedder: vectors
```

| Clé                               | Rôle                                                               |
| --------------------------------- | ------------------------------------------------------------------ |
| `dimensions`                      | la taille des vecteurs                                             |
| `send_dimensions`                 | `true` demande cette taille à un modèle qui sait raccourcir ses vecteurs |
| `query_prefix`, `document_prefix` | pour un modèle qui attend un préfixe (`query: `)                   |

Tout point `/embeddings` compatible OpenAI convient ([Mémoire](/fr/docs/agent/memory/)).

## Images

Nestor envoie les images qu’il dessine dans le chat de l’administration et les messageries. Une
image demandée à voix haute reste dans le journal de l’administration.

```yaml
models:
  painter:
    type: image
    provider: openai-compatible
    base_url: https://openrouter.ai/api/v1
    api_key: ${MODEL_API_KEY}
    model: google/gemini-2.5-flash-image
    endpoint: chat
```

`endpoint: images` (par défaut) utilise `/images/generations` ; `chat` utilise Chat Completions,
comme sur OpenRouter. `size` fixe la taille quand le modèle en prend une (`1024x1024`).

On joint Nestor par ses `channels`. Tous partagent un même agent et une même mémoire : une question
posée dans la cuisine peut se poursuivre depuis l’admin. Pour parler à voix haute, voir
[Voix](/fr/docs/voice/).

## Choisir les canaux

<Providers kind="channel" locale="fr">
<ProviderSetup kind="channel" brand="chat">

La **Discussion** de l’admin. `nestor init` l’ajoute :

```yaml
channels:
  - kind: web
```

Chaque discussion est un fil avec son [titre](/fr/docs/models/#rôles) ; la mémoire est commune. Les
réponses s’affichent au fil de l’écriture, avec les outils que Nestor utilise, **Arrêter** en
interrompt une, et une réponse continue quand vous quittez la page. Le résultat d’une tâche arrive
dans la discussion qui l’a demandée.

Ouverte aux comptes de l’admin liés à une personne du foyer ; le propriétaire que crée
`nestor init` est lié à la première.

</ProviderSetup>
<ProviderSetup kind="channel" brand="telegram">

Créez un bot avec [@BotFather](https://t.me/BotFather) et mettez son jeton dans `.env` :

```ini
TELEGRAM_BOT_TOKEN=123456:ABC-...
```

```yaml
channels:
  - kind: telegram
    token: ${TELEGRAM_BOT_TOKEN}
```

Pour trouver votre identifiant, écrivez au bot : le journal du serveur affiche l’identifiant de
chaque inconnu qu’il ignore.

</ProviderSetup>
<ProviderSetup kind="channel" brand="discord">

Dans le [Developer Portal](https://discord.com/developers/applications), créez une application,
ajoutez un bot, activez son intent **Message Content** et invitez-le sur votre serveur.

```yaml
channels:
  - kind: discord
    token: ${DISCORD_BOT_TOKEN}
```

Il répond aux messages directs, et aux messages qui le mentionnent dans un serveur.

</ProviderSetup>
<ProviderSetup kind="channel" brand="slack">

Créez une app Slack avec le Socket Mode, un jeton d’application (`connections:write`) et un jeton de
bot avec `chat:write`, `files:read`, `files:write`, `im:history` et `app_mentions:read`, abonné à
`message.im` et `app_mention`. Aucune adresse publique n’est nécessaire.

```yaml
channels:
  - kind: slack
    app_token: ${SLACK_APP_TOKEN}
    bot_token: ${SLACK_BOT_TOKEN}
```

Il répond aux messages directs et aux mentions.

</ProviderSetup>
<ProviderSetup kind="channel" brand="matrix">

Créez un compte pour le bot sur un serveur d’accueil, récupérez son jeton d’accès et invitez-le dans
un salon.

```yaml
channels:
  - kind: matrix
    homeserver: https://matrix.org
    token: ${MATRIX_TOKEN}
```

Les salons chiffrés ne sont pas lus : créez le salon sans chiffrement.

</ProviderSetup>
<ProviderSetup kind="channel" brand="signal">

Enregistrez un numéro dans [signal-cli-rest-api](https://github.com/bbernhard/signal-cli-rest-api),
en mode `normal` ou `native`.

```yaml
channels:
  - kind: signal
    url: http://signal:8080
    number: "+33612345678"
```

Il répond aux messages directs et aux groupes. Un message vocal reçoit une réponse écrite.

</ProviderSetup>
<ProviderSetup kind="channel" brand="whatsapp">

Un numéro WhatsApp Business par la Cloud API de Meta. Dans le tableau de bord de l’app Meta, ajoutez
WhatsApp, récupérez l’identifiant du numéro, un jeton permanent d’utilisateur système et le secret de
l’app. Dirigez le webhook vers `https://<votre hôte>/whatsapp` (transmis au port 8473) avec un jeton
de vérification de votre choix.

```yaml
channels:
  - kind: whatsapp
    phone_number_id: "1098…"
    token: ${WHATSAPP_TOKEN}
    verify_token: ${WHATSAPP_VERIFY_TOKEN}
    app_secret: ${WHATSAPP_APP_SECRET}
```

Chaque message est vérifié contre la signature de Meta. Une entreprise ne peut écrire librement que
dans les 24 heures qui suivent le dernier message de la personne : un rappel plus tardif peut être
refusé.

</ProviderSetup>
<ProviderSetup kind="channel" brand="email">

Une boîte mail à Nestor : les membres y écrivent, la réponse revient dans le fil.

```yaml
channels:
  - kind: email
    address: nestor@example.org
    username: nestor@example.org
    password: ${NESTOR_MAIL_PASSWORD}
    imap_host: imap.example.org
    smtp_host: smtp.example.org
```

N’importe qui peut écrire un en-tête `From` : seul le courrier que votre serveur a authentifié
(DMARC, ou DKIM et SPF) reçoit une réponse. Désactivez `require_authenticated` seulement pour un pont
local qui n’ajoute pas cet en-tête.

</ProviderSetup>
<ProviderSetup kind="channel" brand="satellites">

Des appareils sur lesquels on tape, auxquels on parle, ou les deux.

```yaml
channels:
  - kind: satellites
    host: 0.0.0.0
```

`host: 0.0.0.0` ouvre le port 8471 à votre réseau. Pour parler à voix haute, ajoutez une
[voix](/fr/docs/voice/). Ensuite, [appairez-les](/fr/docs/satellites/). Tout le monde dans la pièce
peut parler à un satellite ([Locuteurs](/fr/docs/agent/speakers/)).

</ProviderSetup>
<ProviderSetup kind="channel" brand="api">

Nestor répond à `POST /v1/chat/completions` comme un modèle : Open WebUI, LibreChat, un script, ou
Home Assistant par une intégration de conversation qui accepte une adresse (Extended OpenAI
Conversation). Chaque clé appartient à un compte :

```yaml
channels:
  - kind: openai-api
    keys:
      mathis: ${NESTOR_API_KEY}
```

Donnez au client `http://<nestor>:8472/v1`, le modèle `nestor` et cette clé. `host: 0.0.0.0` l’ouvre
aux autres machines. Nestor garde sa propre conversation : seul votre dernier message compte, images
comprises.

</ProviderSetup>
<ProviderSetup kind="channel" brand="ntfy">

Des notifications sur votre téléphone par [ntfy](https://ntfy.sh). Abonnez-vous à un sujet dans
l’app ntfy :

```yaml
channels:
  - kind: ntfy
```

Sur le serveur public, quiconque connaît un sujet peut le lire : choisissez-en un que personne ne
devinerait, ou votre propre serveur avec `url` et `token`. Personne ne répond par ce canal. Chaque
fichier part dans sa propre notification ; ntfy.sh garde les pièces jointes 3 heures, 15 Mo au plus.

</ProviderSetup>
<ProviderSetup kind="channel" brand="webhook">

Chaque message que Nestor envoie de lui-même part en JSON : vers une automatisation Home Assistant,
n8n, un script.

```yaml
channels:
  - kind: webhook
    url: https://homeassistant.local:8123/api/webhook/nestor
    secret: ${WEBHOOK_SECRET}
```

Le corps est `{"to", "text", "attachments"}` ; chaque pièce jointe porte son `kind` (`image`,
`voice`, `audio`, `file`), son `name` et son contenu. Avec `secret`, `X-Nestor-Signature: sha256=…`
le signe, comme GitHub signe ses webhooks.

</ProviderSetup>
</Providers>

## Qui est qui

Chaque personne indique, dans `household`, le compte sous lequel Nestor la connaît sur chaque canal
([Configuration](/fr/docs/configuration/#le-foyer)). Les canaux qui ne font qu’envoyer prennent un
`reach`.

| Canal      | Dans `accounts` ou `reach`                                |
| ---------- | --------------------------------------------------------- |
| Telegram   | `telegram:<identifiant>`                                  |
| Discord    | `discord:<identifiant>`                                   |
| Slack      | `slack:<identifiant de membre>`                           |
| Matrix     | `matrix:@vous:matrix.org`                                 |
| Signal     | `signal:+33…`, votre numéro                               |
| WhatsApp   | `whatsapp:<votre numéro, chiffres seuls>`                 |
| E-mail     | `email:vous@example.org`                                  |
| API OpenAI | `openai-api:<nom de la clé>`, par exemple `openai-api:mathis` |
| ntfy       | `reach: "ntfy:<sujet>"`                                   |
| Webhook    | `reach: "webhook:<to>"`, envoyé comme `to`                |


## Photos et messages vocaux

Les canaux de messagerie, dont la discussion de l’admin, transmettent les fichiers avec leur légende.
Nestor les garde avec son journal, où l’admin les montre. La discussion accepte jusqu’à 10 fichiers
de 20 Mo chacun par message.

| Reçu               | Ce que fait Nestor                                                                                     |
| ------------------ | ------------------------------------------------------------------------------------------------------ |
| message vocal      | le transcrit ; répond par un vocal quand un modèle de synthèse est défini et que le canal en envoie ([Voix](/fr/docs/voice/#messages-vocaux)) |
| photo              | la montre à un modèle qui voit les images (`vision: true`, `anthropic`, `gemini`) ; sinon, le modèle dit qu’il ne la voit pas |
| PDF, fichier texte | le modèle en lit le texte par parties ; un scan n’a pas de texte, et le modèle le dit. `anthropic` et `gemini` lisent en entier les deux derniers PDF, scans compris |
| tout autre fichier | le nomme au modèle, qui dit qu’il ne peut pas l’ouvrir                                                  |

Ce que Nestor envoie part avec sa réponse, sous son nom : les [images](/fr/docs/models/#images)
qu’il dessine, les documents et fichiers audio qu’une tâche produit. Toutes les messageries et la
discussion de l’admin les envoient.

## Mentions

Sur tous les canaux, un message peut nommer avec `@` ce dont il parle :

| Écrit      | Nomme                                                  | Nestor                                          |
| ---------- | ------------------------------------------------------ | ----------------------------------------------- |
| `@sam`     | une personne, par son `id`                             | lui écrit ce qui lui est destiné                |
| `@cuisine` | une pièce, par sa zone Home Assistant                  | fait dans cette pièce ce que demande le message |
| `@hermes`  | un [exécutant](/fr/docs/executors/), par son nom       | lui confie cette partie du travail              |
| `@gmail`   | un service d’un [compte connecté](/fr/docs/accounts/)  | utilise pour cela les outils de ce compte       |

Un compte Google répond à `@gmail` ou `@calendar`, une boîte IMAP à `@mail`, le serveur MCP de Linear
à `@linear`. Quand deux comptes portent le même nom, le moins de l’adresse qui les distingue le suit :
`@calendar-alex`, ou `@calendar-alex-gmail`.

- La casse et les accents ne comptent pas. Les noms répondent à des alias : le nom d’une personne ou
  d’une pièce (`@Léa`, `@salle-à-manger`), l’adresse d’un compte ou son début.
- Un nom qui ne correspond à rien, ou une adresse e-mail, reste un mot.
- Chacun ne nomme que ce qu’il a le droit d’utiliser : ses propres comptes et ceux du foyer.

La discussion de l’admin propose les noms dès qu’on tape `@`. Chaque nom est journalisé avec le tour
et indiqué au modèle.

## Quand une conversation se termine

Après un silence, le message suivant ouvre une nouvelle conversation et la précédente rejoint la
[mémoire](/fr/docs/agent/memory/).

| Canal       | Silence   |
| ----------- | --------- |
| à voix haute | 5 minutes |
| écrit       | 4 heures  |

`conversation_ends_after_s` le change pour un canal.

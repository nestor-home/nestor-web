[Voix](/fr/docs/voice/).

## Choisir les canaux

<Providers kind="channel" locale="fr">
<ProviderSetup kind="channel" brand="chat">

La **Discussion** de l’admin, ajoutée par `nestor init` :

```yaml
channels:
  - kind: web
```

Chaque discussion a son [titre](/fr/docs/models/#rôles). **Arrêter** interrompt une réponse ;
quitter la page, non. Le résultat d’une tâche arrive dans la discussion qui l’a demandée. Ouverte
aux comptes de l’admin liés à une personne.

</ProviderSetup>
<ProviderSetup kind="channel" brand="telegram">

Créez un bot avec [@BotFather](https://t.me/BotFather), jeton dans `.env` :

```ini
TELEGRAM_BOT_TOKEN=123456:ABC-...
```

```yaml
channels:
  - kind: telegram
    token: ${TELEGRAM_BOT_TOKEN}
```

Votre identifiant : écrivez au bot, le log affiche chaque identifiant ignoré.

</ProviderSetup>
<ProviderSetup kind="channel" brand="discord">

Dans le [Developer Portal](https://discord.com/developers/applications) : une application, un bot
avec l’intent **Message Content**, invité sur votre serveur.

```yaml
channels:
  - kind: discord
    token: ${DISCORD_BOT_TOKEN}
```

Répond aux messages directs et aux mentions.

</ProviderSetup>
<ProviderSetup kind="channel" brand="slack">

Une app Slack en Socket Mode (sans adresse publique), un jeton d’application (`connections:write`)
et un jeton de bot avec `chat:write`, `files:read`, `files:write`, `im:history` et
`app_mentions:read`, abonné à `message.im` et `app_mention`.

```yaml
channels:
  - kind: slack
    app_token: ${SLACK_APP_TOKEN}
    bot_token: ${SLACK_BOT_TOKEN}
```

Répond aux messages directs et aux mentions.

</ProviderSetup>
<ProviderSetup kind="channel" brand="matrix">

Un compte de bot sur un serveur d’accueil, son jeton d’accès, invité dans un salon.

```yaml
channels:
  - kind: matrix
    homeserver: https://matrix.org
    token: ${MATRIX_TOKEN}
```

Les salons chiffrés ne sont pas lus.

</ProviderSetup>
<ProviderSetup kind="channel" brand="signal">

Un numéro enregistré dans [signal-cli-rest-api](https://github.com/bbernhard/signal-cli-rest-api)
(mode `normal` ou `native`).

```yaml
channels:
  - kind: signal
    url: http://signal:8080
    number: "+33612345678"
```

Répond aux messages directs et aux groupes ; aux vocaux par écrit.

</ProviderSetup>
<ProviderSetup kind="channel" brand="whatsapp">

Un numéro WhatsApp Business sur la Cloud API de Meta : l’identifiant du numéro, un jeton permanent
d’utilisateur système, le secret de l’app. Webhook : `https://<votre hôte>/whatsapp` (transmis au
port 8473), avec un jeton de vérification de votre choix.

```yaml
channels:
  - kind: whatsapp
    phone_number_id: "1098…"
    token: ${WHATSAPP_TOKEN}
    verify_token: ${WHATSAPP_VERIFY_TOKEN}
    app_secret: ${WHATSAPP_APP_SECRET}
```

La signature de Meta est vérifiée. Au-delà de 24 heures après le dernier message de la personne,
Meta peut refuser un rappel.

</ProviderSetup>
<ProviderSetup kind="channel" brand="email">

La boîte mail de Nestor ; la réponse revient dans le fil.

```yaml
channels:
  - kind: email
    address: nestor@example.org
    username: nestor@example.org
    password: ${NESTOR_MAIL_PASSWORD}
    imap_host: imap.example.org
    smtp_host: smtp.example.org
```

Seul le courrier authentifié (DMARC, ou DKIM et SPF) reçoit une réponse. Désactivez
`require_authenticated` seulement pour un pont local.

</ProviderSetup>
<ProviderSetup kind="channel" brand="satellites">

```yaml
channels:
  - kind: satellites
    host: 0.0.0.0
```

`host: 0.0.0.0` ouvre le port 8471 à votre réseau. Ajoutez une [voix](/fr/docs/voice/), puis
[appairez les appareils](/fr/docs/satellites/).

</ProviderSetup>
<ProviderSetup kind="channel" brand="api">

Nestor répond à `POST /v1/chat/completions` comme un modèle, pour Open WebUI, LibreChat, un script
ou Home Assistant (Extended OpenAI Conversation). Chaque clé appartient à un compte :

```yaml
channels:
  - kind: openai-api
    keys:
      mathis: ${NESTOR_API_KEY}
```

Client : `http://<nestor>:8472/v1`, modèle `nestor`. `host: 0.0.0.0` l’ouvre aux autres machines.
Seul votre dernier message compte : Nestor garde sa propre conversation.

</ProviderSetup>
<ProviderSetup kind="channel" brand="ntfy">

Des notifications sur le téléphone par [ntfy](https://ntfy.sh), à sens unique :

```yaml
channels:
  - kind: ntfy
```

Sur le serveur public, quiconque connaît le sujet le lit : choisissez-en un introuvable, ou réglez
votre propre `url` et `token`. ntfy.sh garde les pièces jointes 3 heures, 15 Mo au plus.

</ProviderSetup>
<ProviderSetup kind="channel" brand="webhook">

Chaque message que Nestor envoie de lui-même part en JSON (Home Assistant, n8n, un script).

```yaml
channels:
  - kind: webhook
    url: https://homeassistant.local:8123/api/webhook/nestor
    secret: ${WEBHOOK_SECRET}
```

Corps : `{"to", "text", "attachments"}`, chaque pièce jointe avec `kind` (`image`, `voice`,
`audio`, `file`), `name` et contenu. Avec `secret`, signé dans `X-Nestor-Signature: sha256=…`, comme
chez GitHub.

</ProviderSetup>
</Providers>

## Qui est qui

Les [`accounts`](/fr/docs/configuration/#le-foyer) de chaque personne ; les canaux qui ne font
qu’envoyer prennent un `reach`.

| Canal      | Dans `accounts` ou `reach`                                |
| ---------- | --------------------------------------------------------- |
| Telegram   | `telegram:<identifiant>`                                  |
| Discord    | `discord:<identifiant>`                                   |
| Slack      | `slack:<identifiant de membre>`                           |
| Matrix     | `matrix:@vous:matrix.org`                                 |
| Signal     | `signal:+33…`, votre numéro                               |
| WhatsApp   | `whatsapp:<votre numéro, chiffres seuls>`                 |
| E-mail     | `email:vous@example.org`                                  |
| API OpenAI | `openai-api:<nom de la clé>`, par exemple `openai-api:mathis` |
| ntfy       | `reach: "ntfy:<sujet>"`                                   |
| Webhook    | `reach: "webhook:<to>"`, envoyé comme `to`                |


## Photos et messages vocaux

Les messageries et la discussion de l’admin transmettent les fichiers ; l’admin les montre dans le
journal. La discussion accepte 10 fichiers de 20 Mo par message.

| Reçu               | Ce que fait Nestor                                                                                     |
| ------------------ | ------------------------------------------------------------------------------------------------------ |
| message vocal      | le transcrit ; répond par un vocal quand un modèle de synthèse est défini et que le canal en envoie ([Voix](/fr/docs/voice/#messages-vocaux)) |
| photo              | la montre à un modèle qui voit les images (`vision: true`, `anthropic`, `gemini`) ; sinon, le modèle dit qu’il ne la voit pas |
| PDF, fichier texte | le modèle en lit le texte par parties, un fichier étant reconnu à son contenu et à son nom quel que soit le type annoncé par le canal ; un scan n’a pas de texte, et le modèle le dit. `anthropic` et `gemini` lisent en entier les deux derniers PDF, scans compris |
| tout autre fichier | le nomme au modèle avec son type et sa taille ; il ne peut pas l’ouvrir, mais un [exécutant](/fr/docs/executors/) le peut |

Toutes les messageries envoient les fichiers avec la réponse : [images](/fr/docs/models/#images),
documents et audio d’une tâche.

## Mentions

| Écrit      | Nomme                                                  | Nestor                                          |
| ---------- | ------------------------------------------------------ | ----------------------------------------------- |
| `@sam`     | une personne, par son `id`                             | lui écrit ce qui lui est destiné                |
| `@cuisine` | une pièce, par sa zone Home Assistant                  | fait dans cette pièce ce que demande le message |
| `@tele`    | un appareil de la [carte de la maison](/fr/docs/home/#la-carte-de-la-maison), par son nom | sait de quoi parle le message |
| `@hermes`  | un [exécutant](/fr/docs/executors/), par son nom       | lui confie cette partie du travail              |
| `@gmail`   | un service d’un [compte connecté](/fr/docs/accounts/)  | utilise pour cela les outils de ce compte       |

Services : `@gmail` ou `@calendar` (Google), `@mail` (IMAP), `@linear` (son serveur MCP). Deux
comptes de même nom se distinguent par leur adresse : `@calendar-alex`, `@calendar-alex-gmail`.

- La casse et les accents ne comptent pas ; noms, adresses et leur début servent d’alias.
- Un nom qui ne correspond à rien, ou une adresse e-mail, reste un mot.
- Chacun ne nomme que ce qu’il a le droit d’utiliser.

## Quand une conversation se termine

Après un silence, le message suivant ouvre une nouvelle conversation.

| Canal       | Silence   |
| ----------- | --------- |
| à voix haute | 5 minutes |
| écrit       | 4 heures  |

`conversation_ends_after_s` le change pour un canal.

On joint Nestor par ses `channels`. Tous partagent un seul agent et une seule mémoire : une question
posée dans la cuisine peut se poursuivre depuis l’admin.

## Choisir ses canaux

<Providers kind="channel" locale="fr">
<ProviderSetup kind="channel" brand="chat">

Écrivez à Nestor depuis l’admin, dans **Discussion**. `nestor init` l’ajoute :

```yaml
channels:
  - kind: web
```

Chaque discussion a son propre fil, listé sous son [titre](/fr/docs/models/#rôles) ; la mémoire est
la même dans toutes. Les réponses s’affichent au fil de l’écriture, avec les outils que Nestor
utilise, et **Arrêter** en interrompt une. Une réponse continue quand vous quittez la page et
réapparaît quand vous revenez. Ce que Nestor apporte de lui-même pour une discussion, comme le
résultat d’une tâche, y arrive.

La discussion est ouverte aux comptes de l’admin liés à une personne du foyer ; le propriétaire
que crée `nestor init` est lié à la première. Elle accepte les photos, les fichiers et les messages
vocaux enregistrés dans le navigateur : voir [plus bas](#photos-et-messages-vocaux).

</ProviderSetup>
<ProviderSetup kind="channel" brand="telegram">

Créez un bot avec [@BotFather](https://t.me/BotFather) et mettez son jeton dans `.env` :

```ini
TELEGRAM_BOT_TOKEN=123456:ABC-...
```

```yaml
channels:
  - kind: telegram
    token: ${TELEGRAM_BOT_TOKEN}
```

Ajoutez `"telegram:<votre identifiant>"` à vos `accounts` dans `household`. Pour le trouver,
écrivez au bot : le journal du serveur affiche l’identifiant de chaque inconnu qu’il ignore. Il lit
aussi les photos et les messages vocaux : voir [plus bas](#photos-et-messages-vocaux).

</ProviderSetup>
<ProviderSetup kind="channel" brand="satellites">

Des appareils sur lesquels on tape, auxquels on parle, ou les deux. À l’écrit :

```yaml
channels:
  - kind: satellites
    host: 0.0.0.0
```

`host: 0.0.0.0` ouvre le port 8471 à votre réseau. À voix haute, ajoutez une [voix](#voix). Ensuite,
[appairez-les](/fr/docs/satellites/). Tout le monde dans la pièce peut parler à un satellite : voir
[Locuteurs](/fr/docs/agent/speakers/).

</ProviderSetup>
</Providers>

## Voix

Parler à voix haute demande l’extra `voice`, `nestor-home[voice]` ([Installer](/fr/docs/install/)).
L’image Docker le contient.

<Providers kind="speech" locale="fr">
<ProviderSetup kind="speech" brand="elevenlabs">

Une seule clé couvre deux modèles : l’un entend les gens (Scribe v2 Realtime), l’autre donne sa voix
à l’assistant (v4 Turbo). Ce sont des [modèles](/fr/docs/models/#entendre-et-parler), nommés dans le
bloc `voice`.

```ini
ELEVENLABS_API_KEY=sk_...
```

```yaml
models:
  ears:
    type: transcription
    provider: elevenlabs
    api_key: ${ELEVENLABS_API_KEY}
  voice:
    type: speech
    provider: elevenlabs
    api_key: ${ELEVENLABS_API_KEY}
    voice_id: GPAQQPp9dazaB2bl4zg9

channels:
  - kind: satellites
    host: 0.0.0.0
    voice:
      transcription: ears
      speech: voice
```

`voice_id` est n’importe quelle voix de votre bibliothèque. La transcription attend de l’anglais,
sauf si le modèle fixe `language` (`fr`, `de`…). Les messages vocaux passent par `file_model`
(`scribe_v2`) : le modèle temps réel ne lit pas de fichiers.

</ProviderSetup>
<ProviderSetup kind="speech" brand="openai">

Toute API qui parle `/audio/transcriptions` et `/audio/speech` comme OpenAI : OpenAI, Groq et
Mistral pour entendre, OpenAI pour parler.

```yaml
models:
  ears:
    type: transcription
    provider: openai-compatible
    base_url: https://api.groq.com/openai/v1
    api_key: ${GROQ_API_KEY}
    model: whisper-large-v3-turbo
  voice:
    type: speech
    provider: openai-compatible
    base_url: https://api.openai.com/v1
    api_key: ${OPENAI_API_KEY}
    model: gpt-4o-mini-tts
    voice: alloy
```

La transcription entend la langue du foyer, sauf si `language` en dit une autre. Les satellites
entendent un tour une fois fini : les premiers mots l’attendent.

</ProviderSetup>
<ProviderSetup kind="speech" brand="nvidia">

Parakeet TDT v3 entend 25 langues européennes sur la machine de Nestor : pas de clé, rien de ce qui
est dit ne sort de la maison. Il demande `nestor-home[voice,voice-id]`, télécharge un demi-gigaoctet
une fois et prend environ 1 Go de mémoire.

```yaml
models:
  ears:
    type: transcription
    provider: sherpa-onnx
    model: parakeet-v3
```

</ProviderSetup>
<ProviderSetup kind="speech" brand="kokoro">

Kokoro parle sur votre machine par un serveur qui parle l’API d’OpenAI, comme Kokoro-FastAPI ou
speaches. Lancez-le à côté de Nestor, puis désignez-le dans un modèle de synthèse ; il ne demande pas
de clé.

```yaml
models:
  voice:
    type: speech
    provider: openai-compatible
    base_url: http://localhost:8880/v1
    model: kokoro
    voice: ff_siwis
```

`ff_siwis` est la voix française de Kokoro ; `af_heart` et `bm_george` parlent anglais.

</ProviderSetup>
<ProviderSetup kind="speech" brand="whisper">

Whisper entend sur votre machine par un serveur qui parle l’API d’OpenAI, comme speaches ou le serveur
de whisper.cpp. Désignez-le dans un modèle de transcription ; il ne demande pas de clé.

```yaml
models:
  ears:
    type: transcription
    provider: openai-compatible
    base_url: http://localhost:8000/v1
    model: Systran/faster-whisper-small
```

</ProviderSetup>
</Providers>

Le bloc `voice` accepte aussi :

- `style` : comment l’assistant écrit pour cette voix, par exemple ses balises d’expression ;
- `fallback_clips` : un dossier avec `stt.wav` et `tts.wav`, enregistrés dans la même voix, joués
  quand le modèle de parole est en panne.

## Photos et messages vocaux

Les canaux de messagerie, dont la discussion de l’admin, transmettent les photos, messages vocaux,
fichiers audio et documents, avec leur légende. Nestor les garde avec son journal, où l’admin les
montre. La discussion accepte jusqu’à 10 fichiers de 20 Mo chacun par message.

- Un message vocal est transcrit par un modèle `transcription`. Quand un modèle `speech` est défini
  et que le canal sait envoyer des vocaux, la réponse en est un aussi.
- Une photo va au modèle quand son profil voit les images (`vision: true`). Sinon, le modèle dit
  qu’il ne la voit pas.
- Un PDF ou un fichier texte est lu : le modèle en lit le texte par parties, là où il a été envoyé
  ou pour qui l’a envoyé. Un scan n’a pas de texte à lire, et le modèle le dit.
- Tout autre fichier est nommé au modèle, qui dit qu’il ne peut pas l’ouvrir.

Les images que Nestor dessine partent avec sa réponse, sur les canaux qui montrent les images ([Images](/fr/docs/models/#images)).

```yaml
models:
  chat:
    type: language
    provider: openai-compatible
    base_url: https://openrouter.ai/api/v1
    api_key: ${MODEL_API_KEY}
    model: anthropic/claude-haiku-5.5
    vision: true
  ears:
    type: transcription
    provider: elevenlabs
    api_key: ${ELEVENLABS_API_KEY}
    language: fr
  voice:
    type: speech
    provider: elevenlabs
    api_key: ${ELEVENLABS_API_KEY}
    voice_id: GPAQQPp9dazaB2bl4zg9
```

`agent.transcription` et `agent.speech` nomment ces modèles ; chacun prend par défaut le seul de
son type ([Rôles](/fr/docs/models/#rôles)).

## Mentions

Sur tous les canaux, un message peut nommer avec `@` ce dont il parle :

| Écrit      | Nomme                                                | Nestor                                          |
| ---------- | ---------------------------------------------------- | ----------------------------------------------- |
| `@sam`     | une personne du foyer                                | lui écrit ce qui lui est destiné                |
| `@cuisine` | une pièce de la maison, vue par Home Assistant       | fait dans cette pièce ce que demande le message |
| `@hermes`  | un [exécutant](/fr/docs/connections/#tâches-longues) | lui confie cette partie du travail              |
| `@gmail`   | un service d’un compte connecté                      | utilise pour cela les outils de ce compte       |

Une personne se nomme par son `id`, une pièce par sa zone Home Assistant, un exécutant par son nom.
Un connecteur nomme les services de ses comptes : `@gmail` pour un compte Google, `@mail` pour une
boîte IMAP. Avec deux comptes d’un même service, le début de l’adresse les distingue :
`@gmail-alex`.

La casse et les accents ne comptent pas, et les noms répondent à des alias : le nom d’une personne
ou d’une pièce (`@Léa`, `@salle-à-manger`), l’adresse d’un compte ou son début. Un nom qui ne
correspond à rien, ou une adresse e-mail, reste un mot. Chacun ne peut nommer que ce qu’il a le
droit d’utiliser : ses propres comptes et ceux du foyer, jamais ceux d’un autre.

La discussion de l’admin propose les noms dès qu’on tape `@`. Chaque nom est journalisé avec le
tour et indiqué au modèle dans les instructions de ce tour.

## Quand une conversation se termine

Après un silence, le message suivant ouvre une nouvelle conversation et la précédente rejoint la
[mémoire](/fr/docs/agent/memory/). Ce silence est de 5 minutes à voix haute, 4 heures à l’écrit ;
`conversation_ends_after_s` le change pour un canal.

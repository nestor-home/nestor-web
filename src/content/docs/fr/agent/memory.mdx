Nestor garde des **souvenirs**, des faits durables (« Léa est végétarienne »), et des **épisodes**,
le sujet de chaque conversation passée. Les deux se reconstruisent depuis le journal. La mémoire est
généreuse : une ligne ignorée coûte peu, un souvenir qui manque coûte une mauvaise réponse.

## Ce que porte un tour

<MemoryTurn locale="fr" n={1} />

Les derniers souvenirs sont datés, pour que le modèle garde le plus récent de deux qui se
contredisent, et mis en cache avec la couche du foyer. La couche du tour ajoute les plus anciens que
trouvent les trois derniers messages de qui parle, et ses épisodes, que seuls leurs participants
voient. Des outils atteignent le reste :

| Outil               | Effet                                                                     |
| ------------------- | ------------------------------------------------------------------------- |
| `recall`            | cherche dans les souvenirs et les conversations passées, entre deux dates au besoin |
| `read_conversation` | relit une conversation mot pour mot                                       |
| `remember`          | garde un souvenir                                                         |
| `correct_memory`    | en corrige un                                                             |
| `forget`            | en oublie un                                                              |

## Trouver par les mots et par le sens

<HybridSearch locale="fr" n={2} />

**Par les mots**, l’index plein texte de SQLite classe les résultats, sans tenir compte des accents.
**Par le sens**, un modèle d’embedding transforme la question en vecteur et
[sqlite-vec](https://github.com/asg017/sqlite-vec) renvoie les plus proches. La fusion par rang
réciproque réunit les deux listes. La recherche par le sens est facultative : faites pointer
`memory.embedder` vers un modèle d’embedding.

```yaml
models:
  embed:
    type: embedding
    provider: openai-compatible
    base_url: https://openrouter.ai/api/v1
    api_key: ${MODEL_API_KEY}
    model: openai/text-embedding-3-small
memory:
  embedder: embed
```

Tout serveur d’embeddings compatible OpenAI convient, local compris (`llama-server --embeddings` de
llama.cpp). Les vecteurs se calculent en arrière-plan, et s’y recalculent après un changement de
modèle.

## Quand une conversation est finie

<Consolidation locale="fr" n={3} />

Quand le silence d’une conversation dépasse le délai de tous les médiums de son lieu, le modèle de
consolidation écrit son épisode (quelques phrases et sujets) et garde les faits durables que l’agent
a manqués. Après un arrêt, Nestor rattrape au démarrage suivant.

## Réglages

| Réglage                  | Défaut          | Effet                                                           |
| ------------------------ | --------------- | --------------------------------------------------------------- |
| `memory.strategy`        | `both`          | `recent` : les derniers seuls ; `search` : ce que les mots trouvent seulement |
| `memory.recent`          | 150             | souvenirs dans la couche du foyer                               |
| `memory.found`           | 12              | souvenirs que les mots peuvent ajouter                          |
| `memory.recent_episodes` | 3               | dernières conversations de qui parle                            |
| `memory.found_episodes`  | 4               | conversations plus anciennes que ses mots peuvent ajouter       |
| `memory.embedder`        | aucun           | le modèle d’embedding, pour chercher par le sens                |
| `memory.query_timeout_s` | 1               | secondes pour transformer une question avant de chercher par les mots seuls |
| `memory.consolidation`   | `agent.written` | le modèle qui écrit les épisodes                                |

Chaque modèle est un satellite qui marche, avec un micro, un haut-parleur et un voyant d’état. Il
s’appaire, lance la [suite de conformité](/fr/docs/satellites/conformance/) en CI et prépare ses
releases. Remplacez le voyant par votre matériel.

| Langage    | Dépôt                                                                                                       | Repose sur                                     | Publie sur | Demande                                                                  |
| ---------- | ----------------------------------------------------------------------------------------------------------- | ---------------------------------------------- | ---------- | ------------------------------------------------------------------------ |
| Python     | [nestor-satellite-template-python](https://github.com/nestor-home/nestor-satellite-template-python)         | [SDK Python](/fr/docs/sdks/python/)            | PyPI       | uv ; sous Linux, PortAudio                                               |
| TypeScript | [nestor-satellite-template-typescript](https://github.com/nestor-home/nestor-satellite-template-typescript) | [SDK TypeScript](/fr/docs/sdks/typescript/), sous Node | npm | Node 22.12 ou plus récent, pnpm ; `arecord`/`aplay` sous Linux, SoX sous macOS |
| Rust       | [nestor-satellite-template-rust](https://github.com/nestor-home/nestor-satellite-template-rust)             | [SDK Rust](/fr/docs/sdks/rust/)                | crates.io  | Rust 1.91 ou plus récent, un compilateur C, `cmake` ; sous Linux, ALSA   |

## En partir

<Steps>

1. **Créer votre dépôt** avec **Use this template** sur GitHub, ou :

   ```bash
   gh repo create my-satellite --template nestor-home/nestor-satellite-template-python --public --clone
   ```

2. **Le renommer.** Tout s’écrit `my-satellite` (`my_satellite` en Python) ; le README dit où.

3. **Brancher votre matériel** là où le code dit `TODO(hardware)`. Ne déclarez que ce que
   l’appareil possède.

4. **L’appairer.** Créez un code d’enrôlement avec `nestor satellites add --room salon`, ou dans
   l’administration sous **Satellites**, puis donnez à l’appareil l’URI d’appairage affichée
   (commandes ci-dessous). Les lancements suivants n’ont besoin que de `--core` et `--room`.

</Steps>

```bash
# Python
uv run my-satellite run --room salon --pairing-uri 'nestor+http://nestor.local:8471/?code=K7QF2M9X'
# TypeScript
pnpm build && pnpm start run --room salon --pairing-uri 'nestor+http://nestor.local:8471/?code=K7QF2M9X'
# Rust
cargo run -- run --room salon --pairing-uri 'nestor+http://nestor.local:8471/?code=K7QF2M9X'
```

Sans carte son, ajoutez `--null-audio` (Python, Rust) ou `--input none --output none`
(TypeScript).

## Le tester

Chaque modèle lance la suite de conformité contre sa propre commande, à la version du serveur
inscrite dans `.nestor-version` :

| Langage    | Vérifications et conformité                                                           |
| ---------- | ------------------------------------------------------------------------------------- |
| Python     | `uv run ruff check && uv run ruff format --check && uv run ty check && uv run pytest` |
| TypeScript | `pnpm lint && pnpm typecheck && pnpm test && pnpm conformance`                        |
| Rust       | `cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test`        |

La CI lance la même chose sur chaque pull request et finit par un seul job `ci`, à exiger dans les
règles de vos branches.

## Le publier

release-please transforme les titres Conventional Commits en pull request de release. Son job
appelle un workflow partagé de nestor-home qui ne tourne que dans nestor-home : remplacez-le par le
job commenté juste en dessous. La publication est commentée elle aussi : enregistrez un trusted
publisher, puis décommentez le job de publication. Le README détaille les étapes.

Le `--managed` du modèle Python permet à une personne de mettre l’appareil à jour depuis Nestor une
fois qu’il est sur PyPI. Les modèles TypeScript et Rust nomment leur paquet dans le manifeste ;
donnez-leur un `updater` pour faire de même
([Mises à jour](/fr/docs/satellites/protocol/#10-mises-à-jour)).

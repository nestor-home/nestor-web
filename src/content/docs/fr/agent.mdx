## Les parties

<SystemMap locale="fr" n={1} />

Le **cœur** ne dépend d’aucun fournisseur ; tout le reste est un **adaptateur** derrière un
contrat. Au redémarrage, Nestor retrouve dans le [journal](/fr/docs/agent/journal/) les
conversations ouvertes, les tâches, les alertes et les messages non livrés.

## Un tour

<TurnFlow locale="fr" n={2} />

Une **conversation** regroupe les tours proches dans le temps. Finie, le modèle ne la relit plus ; les souvenirs restent. Des messages envoyés ensemble reçoivent
leurs réponses dans l’ordre.

À l’oral, Nestor parle pendant que le modèle écrit encore. Tout mot l’arrête, ou 1,2 s de parole,
sauf un acquiescement (« ouais », « mmh », « yeah », « ok », en français ou en anglais). Quand le modèle ou un service de voix tombe,
Nestor le dit (`conversation.fallback`).

## Les outils

Un outil plus lent que l’attente du tour continue en arrière-plan, et Nestor en dit le résultat
plus tard. Un long résultat est mis de côté, lu avec `read_result` et `search_result`. Ce qui prend des minutes part chez un
[exécutant](/fr/docs/executors/).

| Réglage                                | Défaut                        | Effet                                   |
| -------------------------------------- | ----------------------------- | --------------------------------------- |
| `agent.spoken_tool_wait_s`             | 3                             | secondes d’attente d’un outil à l’oral  |
| `agent.written_tool_wait_s`            | 20                            | secondes d’attente d’un outil à l’écrit |
| `agent.tool_result_chars`              | 8000                          | au-delà, le résultat est mis de côté    |
| `conversation_ends_after_s`, par canal | 5 min à l’oral, 4 h à l’écrit | silence qui termine une conversation    |

## Ce que Nestor sait de lui-même

Au démarrage, Nestor dresse la carte de ses parties d’après les [plugins](/fr/docs/plugins/#fiches)
installés et la configuration :

| État        | Ce que dit la carte                                          |
| ----------- | ------------------------------------------------------------ |
| branché     | ses noms dans la configuration et sa santé                   |
| installé    | installé, pas configuré                                      |
| absent      | pas installé, avec le `pip install` qui l’ajoute             |
| ailleurs    | un paquet de satellite, qui tourne sur son propre appareil   |

Quand on lui demande ce qu’il sait faire, connecter ou utiliser, ou avant de dire qu’il ne peut pas,
l’agent appelle `about_nestor`. Il répond d’après la carte et la section de ces docs qui correspond,
lue en ligne ; hors ligne, d’après la carte seule.

## Les consignes

<PromptLayers locale="fr" n={3} />

La couche du foyer dit aussi comment l’agent fonctionne en ce moment (une recherche web sur offres
gratuites, par exemple), d’après les `notes()` de chaque composant. L’agent le mentionne quand cela
touche à la demande.

## Les modèles par rôle

Faites pointer les rôles vers des profils de `models`. Un seul modèle ne demande rien de plus.

```yaml
models:
  rapide:
    type: language
    provider: openai-compatible
    base_url: https://openrouter.ai/api/v1
    api_key: ${MODEL_API_KEY}
    model: anthropic/claude-haiku-5.5
  soigne:
    type: language
    provider: openai-compatible
    base_url: https://openrouter.ai/api/v1
    api_key: ${MODEL_API_KEY}
    model: anthropic/claude-sonnet-5.5

agent:
  spoken: rapide
  written: soigne
```

| Rôle                   | Sert à                                | S’il est omis   |
| ---------------------- | ------------------------------------- | --------------- |
| `agent.spoken`         | répondre à l’oral                     | `agent.written` |
| `agent.written`        | répondre à l’écrit                    | `agent.spoken`  |
| `agent.titles`         | titrer chaque discussion              | `agent.written` |
| `alerts.model`         | trier ce qui arrive pour les alertes  | `agent.written` |
| `memory.consolidation` | résumer chaque conversation finie     | `agent.written` |

Tous les rôles : [Modèles](/fr/docs/models/).

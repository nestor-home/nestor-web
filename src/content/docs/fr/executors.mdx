Ce qui prend des minutes va à un **exécutant**, un agent qui travaille en arrière-plan. Nestor suit la
tâche et rapporte le résultat, avec ses fichiers.

## Réglages communs

Sous `executors` dans `nestor.yaml` :

| Clé           | Ce qu’elle fait                                                                     |
| ------------- | ----------------------------------------------------------------------------------- |
| `kind`        | `hermes`, `codex` ou `claude-code` ; c’est aussi le nom de l’exécutant              |
| `name`        | seulement pour distinguer deux exécutants du même type                              |
| `description` | ce que l’agent peut lui confier : écrivez ce que cet exécutant sait vraiment faire  |

## Arrêt et redémarrage

Une tâche n’est annulée qu’une fois l’arrêt confirmé par l’exécutant ; sinon, elle finit en échec.

| Exécutant   | Où il tourne                               | Quand Nestor redémarre                              |
| ----------- | ------------------------------------------ | --------------------------------------------------- |
| Hermes      | le serveur Hermes                          | la tâche continue                                   |
| Codex       | un `codex app-server` lancé par Nestor     | il s’arrête, et sa tâche est dite interrompue       |
| Codex       | un démon sur un serveur, joint par `command` | la tâche continue : Nestor retrouve son fil       |
| Claude Code | un processus de Nestor                     | sa tâche est dite interrompue                       |

## Hermes

```yaml
executors:
  - kind: hermes
    base_url: https://hermes.example/v1
    api_key: ${HERMES_API_KEY}
    model: research
    description: Searches the web and writes a short report. No access to the house.
```

`model` est le profil d’agent de Hermes.

## Codex

Installez la CLI de [Codex](https://github.com/openai/codex) là où il tourne et connectez-vous
(`codex login`).

```yaml
executors:
  - kind: codex
    working_directory: /srv/codex/work
    sandbox: workspace-write
    description: Writes and runs code in /srv/codex/work. No access to the house.
```

Chaque tâche est un fil Codex. Une demande d’approbation ou de réponse est refusée.

| Clé       | Défaut             | Ce qu’elle fait                                                                              |
| --------- | ------------------ | -------------------------------------------------------------------------------------------- |
| `sandbox` | `workspace-write`  | ce que Codex peut modifier : `read-only`, `workspace-write` ou `danger-full-access`          |
| `model`   | celui de Codex     | le modèle                                                                                    |
| `config`  | aucun              | des réglages de Codex pour chaque tâche, comme dans son `config.toml` (serveurs MCP, réseau dans le bac à sable) |
| `command` | `codex app-server` | comment joindre Codex                                                                        |

Sur un serveur : lancez-y son démon (`codex app-server daemon start`) et joignez-le par `command`.

```yaml
executors:
  - kind: codex
    command: [ssh, codex@server, codex, app-server, proxy]
    working_directory: /srv/codex/work
    description: Writes and runs code on the server, in /srv/codex/work. No access to the house.
```

## Claude Code

[Claude Code](https://github.com/anthropics/claude-code) tourne sans interface (`claude -p`) sur la
machine de Nestor. Installez-le et connectez-vous, ou donnez une clé d’API.

```yaml
executors:
  - kind: claude-code
    working_directory: /home/nestor/work
    allowed_tools: [Read, Glob, Grep, Write, Edit, "Bash(git *)"]
    max_budget_usd: 2
    api_key: ${ANTHROPIC_API_KEY}
    description: Writes and fixes code in /home/nestor/work and commits with git. No access to the house.
```

Avec `permission_mode: dontAsk` (le défaut), seuls les `allowed_tools` s’exécutent.

| Clé              | Défaut                                                  | Ce qu’elle fait                     |
| ---------------- | ------------------------------------------------------- | ----------------------------------- |
| `allowed_tools`  | lire et écrire dans son dossier, chercher sur le web, sans shell | les outils qu’il peut utiliser |
| `max_budget_usd` | aucun                                                   | ce qu’une tâche peut dépenser       |
| `model`          | celui de Claude Code                                    | le modèle                           |
| `api_key`        | le compte avec lequel Claude Code est connecté          | la clé d’API d’Anthropic            |

La première étape d’une tâche dans le journal est son identifiant de session, pour `claude --resume`.

## Fichiers

Codex et Claude Code ont un dossier par tâche sous `working_directory`, avec les fichiers envoyés. Ils
ne rendent que des fichiers de ce dossier : 10 par tâche, `max_file_bytes` chacun (20 Mo) ; le
résultat nomme ceux laissés de côté.

## Les outils de Nestor pour les exécutants

Pendant une tâche, un exécutant peut appeler le serveur MCP de Nestor :

| Outil                           | Ce qu’il fait                                                                                   |
| ------------------------------- | ----------------------------------------------------------------------------------------------- |
| `task_brief`                    | l’objectif, qui l’a demandé, quand et où, la conversation d’où elle vient, les fichiers envoyés |
| `read_file`                     | un lien pour télécharger un fichier envoyé avec la tâche                                        |
| `recall`, `remember`            | ce que Nestor sait de la personne, et un fait appris pour elle                                  |
| `report_progress`               | une étape, visible dans l’admin et quand quelqu’un demande où ça en est                         |
| `ask_requester`, `check_answer` | une question à la personne, puis sa réponse une fois donnée                                     |
| `attach_file`                   | un lien pour déposer un fichier qui part avec le résultat                                       |
| `home_state`                    | qui est à la maison et les pièces occupées, avec un [`home`](/fr/docs/home/)                    |

Ils n’atteignent que les données de qui a demandé. Un lien de téléchargement vaut dix minutes tant que
la tâche tourne, un lien de dépôt une fois.

### Accès

Servi sur `/mcp` de l’admin. Il faut `public_url`, joignable depuis l’exécutant (domaine, VPN,
Tailscale), et `NESTOR_SECRET_KEY`.

| Secret                 | Envoyé dans             | Ce qu’il prouve                                                                                       |
| ---------------------- | ----------------------- | ----------------------------------------------------------------------------------------------------- |
| clé de l’exécutant     | `Authorization: Bearer` | quel exécutant appelle                                                                                |
| capacité de la tâche   | l’argument `task`       | la tâche : créée quand elle est confiée, valable tant qu’elle tourne et seulement avec la clé de cet exécutant |

Les appels sont limités par clé et journalisés.

| Exécutant          | Comment il reçoit le serveur                                                                                          |
| ------------------ | --------------------------------------------------------------------------------------------------------------------- |
| Codex, Claude Code | avec chaque tâche : Nestor crée leur clé, la garde chiffrée et la passe dans les réglages du fil ou un fichier privé |
| Hermes             | déclaré dans son profil, avec `nestor_mcp: true`                                                                      |

Pour Hermes, créez sa clé dans **Système** ou avec `nestor executors key hermes` : affichée une fois,
avec les lignes du `config.yaml` du profil. Renouveler met fin à l’ancienne ;
`nestor executors revoke hermes` la retire.

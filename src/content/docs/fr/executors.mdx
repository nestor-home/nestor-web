Ce qui prend des minutes va à un **exécutant**, un agent qui travaille en arrière-plan. Une tâche est
un fil qui dure : Nestor lui donne des consignes tour après tour, rapporte chaque compte rendu avec
ses fichiers, et vous pouvez y revenir des jours plus tard.

## Réglages communs

Sous `executors` dans `nestor.yaml` :

| Clé           | Ce qu’elle fait                                                                     |
| ------------- | ----------------------------------------------------------------------------------- |
| `kind`        | `hermes`, `codex` ou `claude-code` ; c’est aussi le nom de l’exécutant              |
| `name`        | seulement pour distinguer deux exécutants du même type                              |
| `description` | ce que l’agent peut lui confier : écrivez ce que cet exécutant sait vraiment faire  |
| `sensitive`   | `true` pour un exécutant aux vrais pouvoirs (un serveur, un réseau) : une tâche lancée ou réorientée depuis un appareil partagé est d’abord confirmée par écrit |
| `archive_after_days` | `30` : une tâche finie laissée de côté aussi longtemps est archivée ; vide, jamais |

## Une tâche, tour après tour

| Vous dites | Ce qui se passe |
| --- | --- |
| « Mets à jour le site avec les nouveaux prix » | une tâche s’ouvre et son premier tour commence (`start_task`) |
| « Ajoute aussi la page contact », pendant qu’elle travaille | la consigne entre dans le tour en cours (`continue_task`) |
| « Continue la mise à jour du site », une semaine après | un nouveau tour dans le même fil : l’exécutant se souvient de ce qu’il a fait |
| la réponse à sa question | le tour suivant, dans le même fil, avec les fichiers que vous envoyez |

Un exécutant qui a besoin de vous termine son tour par sa question. La tâche attend alors votre
réponse : rien ne tourne entre-temps. Nestor vous la pose là où vous êtes, vous la rappelle après
3 h, 24 h et 48 h, puis la question attend dans l’admin. Archiver la tâche la ferme. Ce qu’un tour rapporte revient
dans la conversation où sa consigne a été donnée.

| Exécutant | Même fil d’un tour à l’autre | Réorienté pendant qu’il travaille |
| --- | --- | --- |
| Codex | son fil (`turn/start` sur ce fil) | `turn/steer` |
| Claude Code | sa session (`claude --resume`) | un message pendant le tour |
| Hermes | sa session (`session_id`) | `runs/{id}/steer` |

Une tâche appartient à qui l’a demandée. Cette personne et les admins la voient, la réorientent,
l’arrêtent, la renomment et l’archivent, à la voix, par écrit ou depuis l’admin (**En cours**) ;
les autres membres ne la voient pas.

## Arrêt et redémarrage

Un arrêt termine le tour en cours, une fois confirmé par l’exécutant ; sinon, le tour finit en échec. La
tâche reste, prête à continuer. Une consigne qu’un exécutant ne peut pas prendre en cours de travail
arrête d’abord le tour, puis lance le suivant avec elle ; si l’arrêt n’est pas confirmé, la consigne
n’est pas donnée et on vous le dit.

Quand Codex ou Claude Code n’a plus le fil ou la session de la tâche, le tour repart une fois dans un
nouveau, avec les tours d’avant. Hermes ne peut pas le savoir : il ouvre une session vide sous le même
identifiant.

| Exécutant   | Où il tourne                               | Quand Nestor redémarre                              |
| ----------- | ------------------------------------------ | --------------------------------------------------- |
| Hermes      | le serveur Hermes                          | le tour continue                                    |
| Codex       | un `codex app-server` lancé par Nestor     | il s’arrête, et le tour est dit interrompu          |
| Codex       | un démon sur un serveur, joint par `command` | le tour continue : Nestor retrouve son fil       |
| Claude Code | un processus de Nestor                     | le tour est dit interrompu                          |

## Hermes

```yaml
executors:
  - kind: hermes
    base_url: https://hermes.example/v1
    api_key: ${HERMES_API_KEY}
    model: research
    description: Searches the web and writes a short report. No access to the house.
```

`model` est le profil d’agent de Hermes.

## Codex

Installez la CLI de [Codex](https://github.com/openai/codex) là où il tourne et connectez-vous
(`codex login`).

```yaml
executors:
  - kind: codex
    working_directory: /srv/codex/work
    sandbox: workspace-write
    description: Writes and runs code in /srv/codex/work. No access to the house.
```

Chaque tâche est un fil Codex. Une demande d’approbation ou de réponse est refusée.

| Clé       | Défaut             | Ce qu’elle fait                                                                              |
| --------- | ------------------ | -------------------------------------------------------------------------------------------- |
| `sandbox` | `workspace-write`  | ce que Codex peut modifier : `read-only`, `workspace-write` ou `danger-full-access`          |
| `model`   | celui de Codex     | le modèle                                                                                    |
| `config`  | aucun              | des réglages de Codex pour chaque tâche, comme dans son `config.toml` (serveurs MCP, réseau dans le bac à sable) |
| `command` | `codex app-server` | comment joindre Codex                                                                        |

Sur un serveur : lancez-y son démon (`codex app-server daemon start`) et joignez-le par `command`.

```yaml
executors:
  - kind: codex
    command: [ssh, codex@server, codex, app-server, proxy]
    working_directory: /srv/codex/work
    description: Writes and runs code on the server, in /srv/codex/work. No access to the house.
```

## Claude Code

[Claude Code](https://github.com/anthropics/claude-code) tourne sans interface (`claude -p`) sur la
machine de Nestor. Installez-le et connectez-vous, ou donnez une clé d’API.

```yaml
executors:
  - kind: claude-code
    working_directory: /home/nestor/work
    allowed_tools: [Read, Glob, Grep, Write, Edit, "Bash(git *)"]
    max_budget_usd: 2
    api_key: ${ANTHROPIC_API_KEY}
    description: Writes and fixes code in /home/nestor/work and commits with git. No access to the house.
```

Avec `permission_mode: dontAsk` (le défaut), seuls les `allowed_tools` s’exécutent.

| Clé              | Défaut                                                  | Ce qu’elle fait                     |
| ---------------- | ------------------------------------------------------- | ----------------------------------- |
| `allowed_tools`  | lire et écrire dans son dossier, chercher sur le web, sans shell | les outils qu’il peut utiliser |
| `max_budget_usd` | aucun                                                   | ce qu’un tour peut dépenser         |
| `model`          | celui de Claude Code                                    | le modèle                           |
| `api_key`        | le compte avec lequel Claude Code est connecté          | la clé d’API d’Anthropic            |

La première étape d’une tâche dans le journal est son identifiant de session, pour `claude --resume`.

## Fichiers

Codex et Claude Code ont un dossier par tâche sous `working_directory`, le même à chaque tour, avec
les fichiers envoyés avec chaque consigne ; un nom déjà pris dans la tâche reçoit un numéro
(`devis (2).pdf`). Ils ne rendent que des fichiers de ce dossier : 10 par tour,
`max_file_bytes` chacun (20 Mo) ; le compte rendu nomme ceux laissés de côté.

## Les outils de Nestor pour les exécutants

Pendant un tour, un exécutant peut appeler le serveur MCP de Nestor :

| Outil | Ce qu’il fait |
| --- | --- |
| `task_brief` | la consigne, le titre de la tâche, pour qui, la conversation d’où elle vient, les tours d’avant, ses notes, les fichiers envoyés |
| `read_file` | un lien pour télécharger un fichier envoyé avec la tâche |
| `recall` | ce que Nestor sait de la personne pour qui est la tâche |
| `note` | une note gardée avec la tâche pour ses prochains tours, jamais dans la mémoire de quelqu’un |
| `report_progress` | une étape, visible dans l’admin et quand quelqu’un demande où ça en est |
| `attach_file` | un lien pour déposer un fichier qui part avec ce que rapporte le tour |
| `home_state` | qui est à la maison et les pièces occupées, avec un [`home`](/fr/docs/home/) |

Ils n’atteignent que les données de la personne pour qui est la tâche. Un lien de téléchargement vaut
dix minutes tant que le tour travaille, un lien de dépôt une fois. Les étapes ne montrent jamais une
commande shell.

### Accès

Servi sur `/mcp` de l’admin. Il faut `public_url`, joignable depuis l’exécutant (domaine, VPN,
Tailscale), et `NESTOR_SECRET_KEY`.

| Secret                 | Envoyé dans             | Ce qu’il prouve                                                                                       |
| ---------------------- | ----------------------- | ----------------------------------------------------------------------------------------------------- |
| clé de l’exécutant     | `Authorization: Bearer` | quel exécutant appelle                                                                                |
| capacité de la tâche   | l’argument `task`       | la tâche : créée quand elle est confiée, valable tant qu’elle tourne et seulement avec la clé de cet exécutant |

Les appels sont limités par clé et journalisés.

| Exécutant          | Comment il reçoit le serveur                                                                                          |
| ------------------ | --------------------------------------------------------------------------------------------------------------------- |
| Codex, Claude Code | avec chaque tour : Nestor crée leur clé, la garde chiffrée et la passe dans les réglages du fil ou un fichier privé |
| Hermes             | déclaré dans son profil, avec `nestor_mcp: true`                                                                      |

Pour Hermes, créez sa clé dans **Système** ou avec `nestor executors key hermes` : affichée une fois,
avec les lignes du `config.yaml` du profil. Renouveler met fin à l’ancienne ;
`nestor executors revoke hermes` la retire.
